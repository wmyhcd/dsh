# 会话同步

在侧边栏放一个「会话同步」入口（和 IM 机器人同一排），点开有一个按钮：**同步所有会话**。

## 它解决什么

DSH 的每个会话都有一个常驻的 Agent，而 Agent 会**记住自己加入时的那一份 agent 预设（preset）修订版**。

当你改了某个插件行里面的设置、或者更新 / 新装了插件，DSH 的 HMR 会让这条插件行重启，注册表也会退役旧的预设修订版——但只要有 Agent 还引用着旧修订版，那棵树就不会被释放。于是：

- 已经开着的会话继续用旧的工具集和旧的提示词；
- 只有新开的会话才用得上新配置；
- 两个会话之间还可能各自停留在不同的修订版上，看起来像"设置互相打架"。

本插件做的就一件事：对每个在线会话调用 `agentPresets.recompose(agent.ctx, <它自己记着的 preset>)`，把它重新绑到**当前最新的修订版**，同时释放旧树。

## 怎么用

1. 改完插件设置 / 装好新插件；
2. 侧边栏点「会话同步」；
3. 点「同步所有会话」。

列表里会显示每个在线会话、它用的 preset 和当前是空闲还是运行中。同步完成后给一条结果汇总，失败的会话会单独列出来。

## 边界（重要）

- **正在跑的会话会被跳过**，避免打断当前回合。等它空闲了再点一次。
- 列表会列出**所有会话**（来自 `sessionController.list()`），并做两件事：
  1. **剔除已归档的会话** —— 归档状态读 `workspaceRegistry.archivedSessionIds`（和 archive-manager 用的是同一个来源）。读不到时降级为不过滤，并在返回里带 `archivedFiltered: false`；
  2. 用 `agentAvailable` 标注有没有活跃 Agent：
     - **未打开** —— 没有 Agent，打开时自然装配最新配置，不需要同步；
     - **运行中** —— 有 Agent 但正在跑回合，跳过；
     - **空闲** —— 可同步。
- 只对**有活跃 Agent** 的会话做重新绑定。没打开的会话本来就没有 Agent，下次打开时会直接装配最新配置。
- 同步会**换掉会话正在用的工具集和提示词**。已经写在历史里的工具调用不会改写，历史记录本身完全不动。
- 如果某个会话没有记录 preset（属于没有预设的 profile 级装配），它会被跳过并标记 `无预设`。
- 子会话（`origin: 'subagent'` 或带 `parentSessionId`）不会出现在列表里，它们跟随父会话。
- 如果 `sessionController` 读取失败，会退回只列活跃 Agent，并在日志里留一条 `preset-sync: sessionController.list() failed`。
- 客户端文案目前是中文硬编码，没有走 Client 的 locale 服务。

## 接口

Host 侧在 `/api/dsh-preset-sync` 上注册了一个 POST 端点（沿用 DSH 自带的浏览器认证与 Host/Origin 校验），支持两个方法：

| 方法 | 作用 |
|---|---|
| `sync.preview` | 列出所有会话及其 preset、运行状态、是否有活跃 Agent，不做任何修改 |
| `sync.run` | 对可同步的会话逐个重新绑定，可选传 `{ sessionIds: [...] }` 只同步指定会话 |

另外注册一个模型可调用的工具 `preset_sync`：

| 参数 | 说明 |
|---|---|
| `action: 'status'` | 默认。返回会话总数、开着几个、列表来源 |
| `action: 'run'` | 执行同步，返回总数/同步/跳过/失败 |
| `sessionIds` | 可选，只同步这些会话 |

工具注册失败不影响面板，只会在日志里留一条 warning。

配置项：

| 字段 | 默认 | 含义 |
|---|---|---|
| `skipRunning` | `true` | 跳过 `running` 状态的会话 |
| `settleMs` | `1200` | 重新绑定前等待配置重组落地的毫秒数 |
