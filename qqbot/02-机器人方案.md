# QQ 机器人 + AI 陪聊 · 部署方案

## 整体结构

```
QQ 群 / 私聊
     ↕
NapCat  ← 用你的 QQ 号登录，负责收发消息（跑在服务器上）
     ↕  WebSocket
消息处理服务（监听消息、拼上下文、调 AI）
     ↕
AI 接口（DeepSeek / 智谱 / 其他）
     ↕
把回复发回 QQ
```

服务器上真正跑的是 **NapCat + 一个消息处理程序**，两个进程，用 systemd 或 pm2 保活。

## 组件选型（我查过，两个都还活着）

| 组件 | 版本状态 | 干什么 |
|---|---|---|
| **NapCat** | 11,397★，昨天还在更新 | 登录 QQ，提供 API |
| **NoneBot2** | 7,764★，昨天还在更新 | Python 消息框架，插件多 |
| **Koishi** | 6,280★，活跃 | Node 消息框架，有网页控制台 |

**我的建议：NapCat + NoneBot2**

理由：中文文档最全，出问题好搜。Koishi 有图形界面但插件坑多。

如果你想简单，还有一个极简方案：**NapCat + 一个我自己写的 Node 脚本**，代码不到 200 行，你能看懂每一行，出问题我一眼就能定位。少了框架层反而稳。

### 一个月大概花多少

按每天 200 条消息、每条往返约 500 token 算：

```
一天 10 万 token → 一个月 300 万 token → DeepSeek 约 ¥4～5 元/月
```

**比一瓶水还便宜。** 真跑起来远没这么多（群里没人整天聊天）。

## 群里怎么回话（这个必须先设计好）

机器人最难的部分并不是技术实现，而是**它什么时候该说话**。设计不好就会被踢。

四种模式，选一个或者混用：

### 模式 A：只回 @ ← **最稳，推荐新手**
```
@机器人 今天吃什么
```
只有被点名才说话，绝不打扰。

### 模式 B：关键词触发
群里出现「/ai 内容」或者某些词才回。

### 模式 C：随机插话
每条消息有 5% 概率插一句。活跃感强，但**容易翻车**，需要调参数。

### 模式 D：全部回复
群里每条消息都回。**必被踢**，不建议。

### 上下文记忆
- 记住最近 N 条对话（建议 10 条）
- 每个群、每个人**分开记**，别混在一起
- 超过就忘掉最早的

### 人格设定
一句话描述它是什么人，比如：
```
你是一个话不多的技术宅，回答问题简短直接，偶尔冒一句冷幽默。
不要用「作为一个AI」这种开头。
```
这段直接写进系统提示词。

## 部署完是什么样

服务器上会有：

```
/root/napcat/          QQ 登录程序
/root/bot/             消息处理服务
/etc/systemd/system/   两个开机自启服务
```

**掉线会自动重连**，服务器重启也会自己起来。你什么都不用管。

## 风险，说清楚

1. **账号风险**：NapCat 是模拟登录，不是腾讯官方接口。有封号可能。**用小号，别用主号。**
2. **新号敏感**：刚注册的 QQ 号登录容易被风控，建议用养过一段时间的号。
3. **别刷屏**：AI 回复最好延迟 1–3 秒，一次性连发太多消息会触发腾讯风控。
4. **群里说话要克制**：模式 C 的随机插话最容易招人烦。
